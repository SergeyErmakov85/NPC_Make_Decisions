**Курс:** 4. Математические и инструментальные методы поддержки принятия решений
**Формат:** 4 занятия по 2 академических часа
**Версия:** 2.0 от 25.09.2026 (мирный сюжет «поход к горному приюту»; заменяет версию 1.0)

## Часть 0. Что мы делаем

За четыре занятия вы пройдёте путь от таблицы чисел до персонажа, который сам выбирает,
как себя вести.

**Сюжет.** В 2D-игре о пеших походах путешественник (NPC) выходит со стоянки у костра и
должен до темноты добраться до горного приюта. Между ними — три тропы: лесная (длинная,
но под защитой деревьев), нижняя мимо родников (средняя, можно пополнить воду и еду) и
открытый склон (самая короткая, но продуваемая ветром и дождём). В каждый момент
путешественник выбирает один из шести вариантов действий:

| Код | Вариант действий |
|---|---|
| `DIRECT` | идти к приюту напрямик |
| `SHELTERED` | идти защищённой тропой — через лес и мимо навесов |
| `SURVEY` | подняться на смотровую точку и осмотреться |
| `GATHER` | пополнить запасы у родника (или подкрепиться в ягоднике) |
| `WAIT` | переждать непогоду в укрытии |
| `RETURN` | вернуться к стоянке |

Ситуацию описывают пять чисел: силы (`energy`), расстояние до приюта (`dist`), сила
непогоды (`weather`), запас воды и еды (`supplies`) и доступность укрытий (`shelter`).

```
   Ноутбук (Python)                      Unity
   ─────────────────                     ─────
   состояние среды s
        ↓
   матрица решений X(s)   6 вариантов × 5 критериев
        ↓
   веса критериев w(s)    AHP + адаптация под состояние
        ↓
   метод MCDA             Парето, SAW, TOPSIS, MAUT, VIKOR, ELECTRE
        ↓
   политика π(s)          243 ситуации → вариант действий
        ↓
   policy_unity.json  ──────────────────→  DecisionPolicy.Decide()
                                                   ↓
                                           StrategyExecutor
                                                   ↓
                                           путешественник идёт своей тропой
```

Ключевая мысль всего практикума: **«интеллект» NPC — это не магия, а явная модель
предпочтений**. Вы меняете веса критериев в ноутбуке, и путешественник на экране выбирает другую
тропу. На последнем занятии ту же задачу решит нейросеть (PPO), и мы сравним два подхода
по одинаковым метрикам.

### Что должно получиться

| Занятие | Результат |
|---|---|
| 1 | своя матрица AHP с CR < 0,10 и свои веса критериев |
| 2 | файл `policy_unity.json` — таблица политики на 243 состояния |
| 3 | работающая сцена в Unity: путешественник выбирает тропу по вашей политике |
| 4 | обученный PPO-агент и таблица сравнения «MCDA против RL» |

### Два уровня сложности

* **Уровень A (обязательный)** — занятия 1–3. ML-Agents не нужен вообще. Нужны только
  браузер (для ноутбука) и Unity.
* **Уровень B (продвинутый)** — занятие 4. Нужны Python 3.10 и ML-Agents локально.

Если на уровне B что-то не встанет — ничего страшного: уровень A самодостаточен, а
результаты обучения можно взять у преподавателя готовыми и разобрать их.

## Часть 1. Установка

### 1.1. Сводка версий

Версии здесь не рекомендация, а требование. ML-Agents крайне чувствителен к версии Python,
и почти все проблемы на занятии происходят именно из-за неё.

| Компонент | Версия | Для чего | Когда ставить |
|---|---|---|---|
| Unity Hub | последняя | менеджер версий Unity | до занятия 3 |
| Unity Editor | **6000.0 LTS** (Unity 6.0 LTS) | сцена | до занятия 3 |
| Python | **3.10.11** — именно эта | обучение PPO | до занятия 4 |
| pip-пакет `mlagents` | **1.1.0** | `mlagents-learn` | до занятия 4 |
| PyTorch | **~2.2.1** | бэкенд обучения | до занятия 4 |
| Unity-пакет `com.unity.ml-agents` | **4.x** | компонент `Agent` | до занятия 4 |

Почему Python именно 3.10.11: пакет `mlagents` 1.1.0 требует `>=3.10.1, <=3.10.12`, а
3.10.11 — **последний выпуск Python 3.10 с готовым установщиком для Windows** (начиная с
3.10.12 публикуются только исходники). На Python 3.11, 3.12 и 3.13 `pip install mlagents`
завершится ошибкой разрешения зависимостей.

Почему Unity 6000.0 LTS: это версия, на которую ориентируется документация ML-Agents.
Unity 6.3 LTS новее и для уровня A подходит полностью, но встречаются жалобы на конфликт
версий ML-Agents и Inference Engine. Если вам нужен только уровень A — берите любую
Unity 6 LTS. Если планируете уровень B — берите 6000.0 LTS и не экспериментируйте.

### 1.2. Unity Hub и Unity Editor

1. Скачайте Unity Hub с `unity.com/download`, установите, запустите.
2. Войдите в аккаунт Unity (нужен бесплатный Unity ID) и активируйте **Personal**-лицензию:
   Hub → значок профиля → Manage licenses → Add license → Get a free personal license.
3. Вкладка **Installs** → **Install Editor** → в списке **LTS releases** выберите
   `6000.0.xx (LTS)` → Install.
4. В окне выбора модулей отметьте:
   * **Windows Build Support (IL2CPP)** — на будущее, для сборки .exe;
   * **Documentation** — по желанию;
   * **Microsoft Visual Studio Community** — только если у вас ещё нет ни VS, ни
     VS Code, ни Rider. Это ~4 ГБ и 15 минут.
5. Дождитесь окончания (6–10 ГБ, 15–30 минут на нормальном интернете).

> **Ставьте Unity заранее, не на занятии.** Тридцать человек, одновременно качающих по
> 8 ГБ через одну точку доступа, — это гарантированно сорванная пара.

Редактор кода: подойдёт любой. Минимальный вариант — **Visual Studio Code** с расширением
**C# Dev Kit**. В Unity: Edit → Preferences → External Tools → External Script Editor →
выберите свой редактор.

### 1.3. Python 3.10.11 (только для уровня B)

1. `python.org/downloads/release/python-31011/` → **Windows installer (64-bit)**.
2. В установщике **обязательно** поставьте галочку **«Add python.exe to PATH»**.
3. Выберите «Install Now».

### 1.4. ML-Agents (только для уровня B)

Работаем в виртуальном окружении, чтобы не засорять системный Python.

```powershell
# 1. Создаём папку для окружения (можно любую, например рядом с проектом Unity)
cd C:\Users\<ваше_имя>\Documents
py -3.10 -m venv mlagents-env

# 2. Активируем
.\mlagents-env\Scripts\activate
# приглашение изменится на (mlagents-env) PS C:\...

# 3. Обновляем pip
python -m pip install --upgrade pip

# 4. PyTorch (версия для процессора — её достаточно, сеть здесь крошечная)
pip install torch~=2.2.1

# 5. Сам ML-Agents
pip install mlagents==1.1.0

# 6. Проверка
mlagents-learn --help
```

Последняя команда должна напечатать справку и завершиться без ошибок. Если напечаталась
справка — окружение готово.

> Если есть видеокарта NVIDIA и хочется ускорения, вместо шага 4 выполните
> `pip install torch~=2.2.1 --index-url https://download.pytorch.org/whl/cu121`.
> Для нашей задачи выигрыш небольшой: сеть из двух слоёв по 256 нейронов обучается
> на процессоре нормально.

**Каждый раз** перед работой с ML-Agents окружение надо активировать:
`.\mlagents-env\Scripts\activate`. Забыли — получите `mlagents-learn: command not found`.

### 2.3. Задание 1: свой профиль ЛПР

Найдите в §4 словарь `prefs_careful` и замените суждения своими. Формат: `("A", "B"): k`
означает «критерий A важнее критерия B в k раз» по шкале Саати 1–9.

```python
prefs_careful = {
    ("progress", "time"): 3,  ("progress", "supply"): 2,  ("progress", "info"): 2,
    ("risk", "progress"):  2,  ("risk", "time"):     4,  ("risk", "supply"):   3,  ("risk", "info"): 3,
    ("info", "time"):      2,  ("info", "supply"):   1,
    ("supply", "time"):    2,
}
```

Придумайте «характер» путешественника и выразите его числами:

* **осторожный краевед** — риск важнее всего, знание местности важнее продвижения;
* **торопыга** — продвижение важнее всего, риск почти не учитывается;
* **хозяйственник** — восстановление сил и запасов важнее скорости.

Перезапустите ячейку. Если `CR ≥ 0,10` — ваши суждения противоречивы (например, A важнее B,
B важнее C, но C важнее A). Ищите противоречие и правьте, пока `CR` не станет меньше 0,10.

### 2.4. Задание 2: своя политика

В §11 замените `W_BASE` на полученные через AHP веса:

```python
policy = build_policy("TOPSIS", w_ahp, adaptive=True)
```

Посмотрите на таблицу распределения вариантов действий. **Если какая-то стратегия не выбирается
ни в одном из 243 состояний — это плохая политика**: часть таблицы мертва, и в игре
вы эту стратегию никогда не увидите. Правьте веса, пока не задействуются хотя бы пять
стратегий из шести.

Посмотрите на карту политики (§11, тепловые карты) и проверьте её на здравый смысл:

* уставший путешественник в сильную непогоду должен переждать или вернуться;
* бодрый путешественник рядом с приютом должен идти напрямик;
* при пустом запасе воды и еды он должен идти к роднику.

Если карта противоречит вашему замыслу — правьте **веса**, а не код.

## Часть 3. Занятие 3. Сцена в Unity (уровень A)

Цель занятия: путешественник ходит по уровню и выбирает тропу по **вашей** политике.

### Шаг 1. Создать проект

Unity Hub → **New project** → шаблон **2D (URP)** (если такого нет — **Universal 2D**) →
имя `CorridorRisk2D` → Create project.

Первое открытие занимает 2–5 минут: Unity компилирует шейдеры URP.

Когда редактор попросит **Import TMP Essentials** — согласитесь. Это нужно для подписи
варианта действий над путешественником.

### Шаг 2. Подключить скрипты

1. Распакуйте `CorridorRisk2D_Scripts.zip`.
2. Скопируйте папку `Assets` из архива **поверх** папки `Assets` вашего проекта
   (в проводнике Windows, при закрытом или открытом Unity — неважно).
   Если в проекте остались скрипты **первой версии** (`ThreatZone.cs`, `Pickup.cs` и т. п.),
   сначала удалите папки `Assets/Scripts` и `Assets/Data` и объект `Level` со сцены.
3. Вернитесь в Unity. Внизу справа покрутится индикатор компиляции.
4. Откройте окно **Console** (Window → General → Console). **Красных ошибок быть не
   должно.** Жёлтые предупреждения допустимы.

Если ошибки есть — смотрите Часть 8.

### Шаг 3. Положить свою политику

1. Перетащите скачанный из Colab `policy_unity.json` в `Assets/Data/`, заменив файл из
   архива (эталонный можно предварительно переименовать в `policy_topsis_reference.json`,
   чтобы было с чем сравнить).
2. Щёлкните по нему в Project и убедитесь, что в Inspector он показан как **TextAsset**
   и виден его текст.

### Шаг 4. Построить уровень

1. Сохраните сцену: File → Save As → `Assets/Scenes/CorridorRisk2D.unity`.
2. Меню **CorridorRisk → Построить уровень из JSON**.

За секунду в сцене появятся 25 путевых точек, 7 участков непогоды, 10 участков укрытий,
родники, ягодники, смотровые точки, стоянка, горный приют, границы поля и три цветные
линии троп. Камера настроится
сама.

> Расставлять всё это руками бессмысленно: при первой же правке геометрии пришлось бы
> переделывать. Скрипт читает тот же JSON, который порождает расчётный `level.py`,
> поэтому модель и сцена гарантированно не расходятся.

Нажмите **F** в окне Scene, выделив объект `Level`, — увидите всю раскладку. Сравните с
`CorridorRisk2D_layout.png`.

### Шаг 5. Создать ассет баланса

Project → правой кнопкой в `Assets` → **Create → CorridorRisk → Balance**.
Назовите `CorridorRiskBalance`. Значения по умолчанию уже выставлены правильно, менять
пока ничего не нужно.

### Шаг 6. Собрать объект Systems

1. В Hierarchy: правой кнопкой → Create Empty → назовите **Systems**, позиция (0, 0, 0).
2. Add Component → **Level Graph**.
   * `Level Json` ← перетащите `Assets/Data/level_corridor_risk_2d.json`
3. Add Component → **Episode Logger**.
   * `Run Id` ← напишите свою фамилию латиницей, например `ivanov`
4. Add Component → **Episode Manager**. Ссылки заполним после того, как появится путешественник.

### Шаг 7. Собрать путешественника (объект Agent)

1. Hierarchy → Create Empty → назовите **Agent**, позиция (−29, 0, 0).
2. Add Component → **Sprite Renderer** → в поле Sprite выберите встроенный **Knob**
   (в окне выбора спрайта переключитесь на вкладку со встроенными ассетами).
   Масштаб Transform поставьте `(1.2, 1.2, 1)`.
3. Add Component → **Circle Collider 2D** → Radius `0.6`, галочку Is Trigger **не** ставить.
4. Add Component → **Agent State**:
   * `Graph` ← объект **Systems**
   * `Balance` ← ассет **CorridorRiskBalance**
5. Add Component → **Agent Motor** (Rigidbody2D добавится сам):
   * `Balance` ← CorridorRiskBalance
   * `State` ← сам объект Agent
6. В появившемся **Rigidbody 2D** проверьте: Body Type = **Kinematic**, Gravity Scale = 0.
7. Add Component → **Agent Triggers**:
   * `State` ← Agent
8. Add Component → **Decision Policy**:
   * `Policy Asset` ← `Assets/Data/policy_unity.json` (**ваш** файл)
   * `Stochastic When Ambiguous` ← включено
   * `Softmax Temperature` ← `0.04`
9. Add Component → **Trail Renderer**:
   * Time `3`, Width `0.25`
   * Materials → Element 0 ← встроенный материал **Sprites-Default**
     (без него след будет ярко-розовым)
10. Подпись над путешественником: правой кнопкой по Agent → 3D Object → **Text — TextMeshPro**.
    Назовите `Label`, позиция `(0, 1.6, 0)`, Font Size `3`, Alignment по центру.
11. На объекте Agent: Add Component → **Strategy Label**:
    * `Label` ← дочерний объект Label
    * `Trail` ← Trail Renderer на Agent

### Шаг 11. Убедиться, что тропа нигде не зашита

Откройте `StrategyExecutor.cs` и поищите по файлу строку «Route», «тропа A», «B», «C».
В логике их нет. Вариант действий задаёт только:

* **цель поиска** — куда идти (метод `TargetNodeFor`);
* **коэффициенты стоимости ребра** — насколько избегать непогоды и держаться укрытий (таблица `Profiles`).

Тропа выбирается сама, как решение задачи поиска кратчайшего пути с этой стоимостью:

$$
c(u \to v \mid a) = \ell(u,v)\cdot\frac{1 + k^a_{\text{weather}}\cdot \overline{\text{weather}}}{1 + k^a_{\text{shelter}}\cdot \overline{\text{shelter}}}
$$

Для `DIRECT` оба коэффициента равны нулю — остаётся чистая длина, и кратчайшей оказывается
центральная тропа по открытому склону (48,5 единиц). Для `SHELTERED` непогода утраивает стоимость, а укрытия её
снижают — и выигрывает верхняя лесная тропа, хотя геометрически она длиннее в 1,39 раза.

**Проверьте сами:** в `Strategy Executor` впишите в `Forced Strategy` значение `DIRECT`,
запустите, посмотрите траекторию. Потом `SHELTERED`. Потом `GATHER`.

## Часть 5. Занятие 4. Обучение с подкреплением (уровень B)

### 5.1. Идея

Мы ставим RL ровно ту же задачу, что решала MCDA: **выбрать один из шести вариантов действий**.
Действие агента — не «идти влево», а индекс варианта действий. Низкоуровневое исполнение остаётся
в `StrategyExecutor` и одинаково у обоих агентов. Только при таком устройстве сравнение
корректно.

Функция награды собирается из тех же пяти критериев и с теми же весами:

$$ r = w_{\text{progress}}\Delta\text{progress} - w_{\text{risk}}\,\Delta\text{energyLost} - w_{\text{time}}\Delta t + w_{\text{supply}}\Delta\text{supply} + w_{\text{info}}\Delta\text{info} $$

Сравните с формулой взвешенной суммы из §3 ноутбука. Это одна и та же конструкция,
применённая в разных местах: в MCDA — к оценкам альтернатив, в RL — к приращениям
состояния. Осознать это — главная цель занятия.

## Часть 6. Разбор кода: где что происходит

Читать в этом порядке. Это то, что разбирается на лекционной части занятия.

### 6.1. `AgentState.cs` — мост между сценой и таблицей

Здесь пять переменных состояния получают числовые значения. **Имена и диапазоны обязаны
совпадать с ноутбуком буква в букву**, иначе `policy_unity.json` будет читаться неверно,
а поведение получится бессмысленным, но правдоподобным — худший вид ошибки.

Обратите внимание на экспоненциальное сглаживание:

```csharp
float k = 1f - Mathf.Exp(-Time.fixedDeltaTime / balance.smoothing);
_weatherEma = Mathf.Lerp(_weatherEma, weather, k);
```

Без него путешественник дёргается на границах участков: один шаг через край участка перебрасывает
`weather01` через границу бина, и стратегия меняется туда-обратно. `smoothing` — первая
ручка, которую стоит крутить, если NPC ведёт себя нервно.

### 6.2. `DecisionPolicy.cs` — чтение таблицы

Метод `Bin()` дискретизирует непрерывное значение в индекс бина, причём **границы берутся
из того же JSON**:

```csharp
public int Bin(string varName, float value) {
    if (!_edges.TryGetValue(varName, out var e)) return 0;
    int i = 0;
    while (i < e.Length && value >= e[i]) i++;
    return i;
}
```

В коде нет ни одного «зашитого» числа: поменяете дискретизацию в ноутбуке — Unity подхватит
её автоматически. Это осознанное проектное решение, а не педантизм: рассинхронизация
границ бинов — самая коварная ошибка в такой связке, потому что всё продолжает работать,
просто неправильно.

`SoftmaxSample()` нужен там, где разрыв между первым и вторым местом мал (`ambiguous`).
Жёсткий `argmax` в таких состояниях делает поведение неестественно детерминированным.

### 6.3. `StrategyExecutor.cs` — исполнение

Две таблицы и один цикл. Таблица `Profiles` задаёт для каждой стратегии коэффициенты
стоимости ребра и множитель скорости. Метод `TargetNodeFor()` — куда идти. Всё.

Гистерезис в цикле решения:

```csharp
if (next != CurrentStrategy && entry.margin >= balance.hysteresis) { ... }
```

Смена стратегии происходит только если новая выигрывает не еле-еле. Поставьте
`hysteresis = 0` и посмотрите, что будет, — это поучительно.

### 6.4. `LevelGraph.cs` — откуда берётся `dist01`

Дейкстра от узла `HUT` считается один раз при старте сцены, дальше `dist01` — это просто
чтение из массива плюс расстояние до ближайшего узла. Поэтому расстояние до приюта —
честная длина пути по проходимому графу, а не расстояние по прямой через участок непогоды.

### 6.5. `EpisodeManager.cs` — генератор стартов

Самая неочевидная часть. `energy` и `supplies` выставляются прямо у путешественника — это его собственные свойства.
`dist` и `shelter` — свойства **места**, поэтому под них подбирается узел спавна. `weather` —
свойство и места, и настроек сцены, поэтому подбирается двумя параметрами: масштабом участков
непогоды и фоновой непогодой.

```csharp
if (raw >= 0.05f) {
    scale   = Mathf.Clamp(tWeather / raw, 0.30f, 2.00f);
    ambient = Mathf.Clamp01(tWeather - raw * scale);
} else {
    scale = 1f; ambient = tWeather;      // узел вне участков непогоды — только фон
}
```

И детерминизм: `new System.Random(baseSeed * 7919 + index)`. Без него сравнивать MCDA и
PPO бессмысленно — они пойдут по разным стартовым ситуациям, и разница в метриках будет
означать что угодно.

## Часть 8. Решение проблем

### Unity: скрипты не компилируются

| Ошибка в Console | Причина | Решение |
|---|---|---|
| `The type or namespace name 'MLAgents' could not be found` | `DecisionAgent.cs` переименован до установки пакета | переименовать обратно в `.cs.txt` либо установить `com.unity.ml-agents` |
| `The type or namespace name 'TMPro' could not be found` | не импортированы TMP Essentials | Window → TextMeshPro → Import TMP Essential Resources |
| `CS0246: LevelGraph not found` | папка `Assets` скопирована не целиком | проверьте, что есть `Assets/Scripts/Level/LevelGraph.cs` |
| `Editor` скрипты ругаются на `UnityEditor` | `LevelBuilder.cs` лежит не в папке `Editor` | путь обязан быть `Assets/Scripts/Editor/` |

### Unity: сцена запускается, но ничего не происходит

| Симптом | Причина | Решение |
|---|---|---|
| `NullReferenceException` при Play | не заполнена ссылка в инспекторе | CorridorRisk → Проверить сцену |
| `[LevelGraph] не назначен levelJson` | пустое поле `Level Json` | перетащить `level_corridor_risk_2d.json` |
| `[DecisionPolicy] не назначен policyAsset` | пустое поле `Policy Asset` | перетащить свой `policy_unity.json` |
| Путешественник стоит на месте | вариант `WAIT` — он пережидает в укрытии | это правильное поведение; смените стартовую ситуацию |
| Путешественник проходит сквозь границы поля | `Rigidbody2D` кинематический — границы поля не удерживают его физически | так и задумано, он ходит по графу тропинок и за поле не выходит |
| `[DecisionPolicy] нет записи 2\|1\|0\|1\|2` | в политике меньше 243 записей | перевыгрузите `policy_unity.json`, проверьте, что `entries` содержит 243 элемента |
| След ярко-розовый | у `Trail Renderer` нет материала | Materials → Element 0 → `Sprites-Default` |
| Подпись не видна | не импортированы TMP Essentials или Font Size слишком мал | импортировать TMP, Font Size = 3 |

### Unity: поведение странное

| Симптом | Причина | Решение |
|---|---|---|
| Путешественник мечется между вариантами | мал гистерезис или мало сглаживание | `hysteresis` → 0,04; `smoothing` → 0,8 |
| Всегда одна и та же стратегия | вырожденная политика | вернуться в ноутбук, §11, проверить распределение стратегий |
| Все эпизоды заканчиваются таймаутом | пустой запас, скорость упала почти до нуля | поднять стартовый `demoSupplies` или проверить `kDrain` |
| Путешественник выбивается из сил за две секунды | стартовал в ядре участка непогоды с малым запасом сил | так бывает; смотрите на доли по 500 эпизодам, а не на один |

### ML-Agents

| Ошибка | Решение |
|---|---|
| `mlagents-learn : не удается распознать` | не активировано окружение: `.\mlagents-env\Scripts\activate` |
| `Couldn't connect to trainer on port 5004` | Unity нажали Play до появления приглашения; остановите и повторите |
| `The Unity environment took too long to respond` | в проекте несколько объектов с `Behavior Parameters`, или Play нажали слишком поздно |
| `Vector Observation size mismatch: expected 16, got N` | не совпадает `Space Size` с тем, что отдаёт `CollectObservations` |
| `Descriptors cannot not be created directly` | `pip install protobuf==3.20.3` |
| `numpy.dtype size changed` | `pip install "numpy<2"` |
| Награда не растёт вообще | проверьте режим Heuristic Only: если и там плохо — дело в сцене, а не в обучении |
